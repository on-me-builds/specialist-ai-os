# specialist-ai-os 事業計画サマリー v0.1

> 作成日: 2026-03-23
> 用途: チームメンバー向け5分共有版

## この事業は何か

specialist-ai-os の主商品仮説は、歯科医院向けの**中断患者リテンションOS**である。これは予約システムを置き換えるサービスではない。既存の予約システムや院内運用はそのままに、中断患者・取りこぼし患者を見える化し、戻せそうな患者から呼び戻す運用を作るサービスである。

売るものは「文章」ではなく「運用」である。医院が本当に困っているのは、FAQ や求人文がないことよりも、忙しくて運用が回らず、既存患者の取りこぼしが放置されていることである。

## なぜこの方向に変わったのか

当初は、医院情報から FAQ、口コミ返信、求人文、Sales Onepager の4文章を自動生成する Product Factory を作っていた。これはローカル実行と n8n simple workflow まで確認済みで、技術的には成立している。

ただし、事業として見ると4文章生成は主商品に向かなかった。代替手段が多く、単体では継続課金しにくく、院長の強い痛みや売上回復に直接つながりにくいからである。HP業者、採用業者、テンプレート、ChatGPT 直打ちで代替されやすく、差別化しにくい。

その一方で、歯科医院の現場では「中断患者がいることはわかっているが、何人いるかも、誰に何を送るかも、運用として回っていない」という問題が強い。さらに、多くの医院はキャンセル率や中断患者数を精緻に取れていない。だからこそ、最初の価値は改善率の約束ではなく、**見える化と最初の運用化**になる。

## 何を売るのか

初期提供は concierge MVP とする。いきなり SaaS を作るのではなく、半手動で実際に運用を回し、価値を検証する。

初期に提供するものは以下である。

- 中断患者候補の整理
- 呼び戻し対象の優先順位づけ
- LINE / SMS / メール等の文面作成
- 医院側配信を前提にした運用設計
- 反応記録
- 再予約導線の整理
- 週次 / 月次の簡易振り返り

初期の基本形は、「こちらが対象整理と文面作成を行い、医院側が送信する」である。こちらが最初から医院の LINE 公式アカウント管理画面に入る前提にはしない。

対象医院は2ルートで考える。Type A は予約履歴や CSV を出せる医院、Type B は数字が弱く、まず2週間の手動記録や見える化シートから始める医院である。

## 4文章生成は何のために残すのか

4文章生成は今後も使うが、主商品ではない。役割は3つである。

- front-end offer として最初の接点を作る
- ヒアリング前後の信頼獲得用のお土産にする
- 医院情報を構造化して、主商品のオンボーディングに使う

つまり、FAQ / 口コミ返信 / 求人文 / onepager は「売る中心」ではなく、「主商品に入る前の入口」として使う。

## 何を売らないのか

今やらないことは明確に固定する。

- 予約システムそのものの開発
- レセコン置き換え
- MEO / 口コミ運用を主戦場にすること
- FAQ や求人文の単体商品化
- いきなり全自動 SaaS 化
- 他業種への横展開
- 大規模な外注体制やコンサル色の強い展開

これは消極策ではなく、焦点を絞るための意思決定である。まず歯科で一本目の勝ち筋を作る。

## どこで勝とうとしているのか

狙うのは crowded な領域ではない。予約システムそのもの、単純なリマインド通知、MEO、求人媒体、文章生成単体は競争が激しい。ここを主戦場にすると、機能比較や価格比較で消耗しやすい。

一方で、中断患者の呼び戻し運用、リコール最適化、既存システムの上に乗る運用改善層は、まだ運用として弱い。機能が一部あっても、実際に回っていない医院が多い。ここに「ツール」ではなく「運用OS」として入るのが勝ち筋である。

立ち位置は明確である。

- 予約システムを置き換えない
- 既存システムの上に乗る
- 成果物より運用ループを売る
- 最初は concierge MVP で学習速度を優先する

## 次に何を検証するのか

最初に見るべきことは、派手な KPI ではなく、事業として成立する前提が揃うかどうかである。

- 中断患者リストを出せるか
- 実際に対象患者を特定できるか
- 医院側が配信を実行できるか
- 既読率
- 返信率
- 再予約率
- 院長が継続したいと思うか
- 月額を払う意思があるか

加えて、定量化しにくいが重要な確認項目もある。院長が「放置されていた問題が見えるようになった」と感じるか、院内で運用担当が決まるか、見える化だけでも価値があると認識されるかである。

直近2〜4週間では、院長ヒアリングを進め、Type A / Type B の候補医院を見つけ、小規模パイロットを回す。すでに院長ヒアリングシート、1枚営業資料、concierge MVP 仕様書、パイロット提案文はあるため、今は資料を増やすより、実戦投入して歩留まりを確認する段階である。

## Short Memo

### 確定事項

- 主商品は中断患者リテンションOS
- 4文章生成は補助資産であり主商品ではない
- 最初の対象は歯科のみ
- 既存システムの上に乗る運用改善を狙う
- 初期は concierge MVP で始める

### 仮説

- 最初に刺さる医院セグメント
- Type A / Type B の現実的な比率
- 月額 3〜5万円帯の受容性
- 既読率、返信率、再予約率の現実ライン

### 次にチームで議論すべきこと

1. 最初に当たる医院候補と検証順
2. Type A / Type B の優先順位
3. 有償化時の最小提供範囲
