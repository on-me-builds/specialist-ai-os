# パイロット成功定義と有償化判断基準（内部メモ）

> v0.1 ― チーム内共有用。営業資料ではない。
> 前提: 営業キットは「見える化」を入口にしている。このメモは、見える化の先で何を確認し、どこで有償化の判断をするかを整理する。

---

## 1. なぜ「見える化」だけでは弱いのか

見える化は導入障壁を下げる。ただし、以下の理由で**それ自体は継続課金の対象にならない**。

- 見える化は1回やれば終わる。毎月払う理由がない
- 「リストが出ました」だけでは、院長は「ふーん」で終わる
- 院長が金を出すのは「戻ってきた」「売上が回復した」という結果に対して
- 見える化の価値は、その先の運用（呼び戻し→反応→再来院）が回って初めて成立する

**見える化は手段。価値は「呼び戻しが回り続けること」にある。**

---

## 2. 初回パイロットで本当に見るべきもの

KPIを追いたくなるが、初回パイロットで見るべきは3つだけ。

| 優先度 | 確認項目 | なぜ重要か |
|:------:|---------|-----------|
| **1** | 院長が「続けたい」と言うか | 数字がどうであれ、この一言が出なければ有償化しない |
| **2** | 呼びかけに対して1人でも反応があるか | ゼロなら仕組みが成立しない。1人でも反応があれば「やれる」証拠になる |
| **3** | リストの取得と配信が現実的に回ったか | 運用として持続可能かの判断。ここが重すぎると月額の価値がない |

逆に、以下は初回パイロットでは追わない。

- 正確な再予約率（サンプルが少なすぎて統計的に無意味）
- 推定売上回収額（初回は金額換算しない。院長に「いくら戻った」と言わない）
- 配信チャネルの最適化（LINEで始める。初回はチャネル比較しない）

---

## 3. 最小成功体験の定義

パイロットを「成功」とみなす最低ライン。

> **10人以上に呼びかけて、1人以上から反応があり、院長が「次もやりたい」と言った。**

これだけ。

- 反応 = 返信、電話、予約のいずれか
- 「既読だけ」は反応に含めない（ただし既読率は記録する）
- 院長の「次もやりたい」は口頭でよい。書面は不要
- 再来院まで至らなくても、反応があれば成功とする

---

## 4. Type A / Type B それぞれの成功条件

| | Type A（データあり） | Type B（感覚ベース） |
|---|---|---|
| **リスト** | CSVから20〜30名を抽出 | 手書き or 口頭で10〜15名を挙げる |
| **配信** | 20名以上に配信 | 10名以上に配信 |
| **反応** | 2名以上 | 1名以上 |
| **見える化の成果** | 中断患者の全体像が数字で見える | 「こんなにいたのか」という気づきが生まれる |
| **成功判定** | 院長が「月次で回したい」と言う | 院長が「もう少しちゃんとやりたい」と言う |
| **有償化の可能性** | 高い。すぐ月額契約に進める | 中。次のサイクルでType Aに寄せる必要あり |

**Type B の追加条件:**
Type B で成功した場合、2回目以降は「予約システムからのCSV出力」に移行してもらう。手書きを毎月続けるのは持続不可能。移行できない場合は有償化を急がない。

---

## 5. 有償化へ移る判断条件

以下の**3つすべて**が揃ったとき、有償化を提案する。

| # | 条件 | 確認方法 |
|---|------|---------|
| 1 | 院長が「続けたい」と明言している | 振り返り面談で確認 |
| 2 | リストの取得が月次で回せる見込みがある | Type A: CSV出力できた / Type B: 次回はCSVに移行する意思がある |
| 3 | 呼びかけに対して反応があった（1名以上） | パイロットレポートで確認 |

**補足:**
- 3つのうち1つでも欠けたら、有償化を急がない
- 条件1が欠けている = pain が弱い。無理に売らない
- 条件2が欠けている = 運用が持続しない。仕組みを先に整える
- 条件3が欠けている = 仕組みが効いていない。メッセージや対象の見直しが先

---

## 6. 有償化しない方がいいケース

以下に該当する場合は、パイロット成功でも有償化を見送る。

| ケース | 理由 |
|--------|------|
| 院長が「成果は出たけど、自分でやれそう」と言った | 我々の介在価値がない。無理に売ると解約される |
| リストが毎月10人以下しか出ない | 配信母数が少なすぎて月額の価値を感じてもらえない |
| LINE友だちが極端に少ない（30人未満） | 配信対象がほとんどいない。先にLINE友だち集めが必要 |
| 院長の本当の課題が別にある（新患集客、スタッフ問題等） | 中断患者呼び戻しでは解決しない。別の提案が必要 |
| 予約システムの操作が極端に難しく、CSV出力が継続できない | 毎月の手動サポートコストが月額を超える |

---

## 7. 継続課金の価値をどう言語化するか

院長に月額を提案するとき、使ってよい言い方と避ける言い方。

### 使ってよい

> 「毎月、取りこぼし患者を自動で拾い上げて、呼び戻すメッセージを回し続ける運用を維持します」

> 「先生やスタッフが毎月やると30分〜1時間かかる作業を、こちらで回します」

> 「呼びかけの文面も、反応を見ながら毎月調整していきます」

> 「一度やって終わりではなく、運用として回し続けることに価値があります」

### 避ける

- ~~「月○万円の売上を回収します」~~（保証できない）
- ~~「キャンセル率を○%改善します」~~（コントロールできない）
- ~~「AIが自動で最適化します」~~（現段階では手動が多い。過剰に見せない）
- ~~「他の医院では○%の成果が出ています」~~（サンプル不足で言えない）

### 月額の正当化ロジック

```
月額 3〜5万円 の内訳（院長に見せる用ではなく、自分たちの整理用）:
  - 毎月のリスト整理・対象選定: 30分
  - メッセージ作成・調整: 30分
  - 配信サポート: 15分
  - 反応記録・追跡: 1時間
  - 月次レポート作成: 30分
  - 合計: 約3時間/月の運用代行

→ 時給換算 1〜1.7万円。代行業務としては妥当な水準。
→ ただし、院長に対しては「時間単価」ではなく「運用が回り続けること」で訴求する。
```

## Short Memo

| 項目 | 内容 |
|------|------|
| **最小成功体験** | 10人に送って1人反応 + 院長が「続けたい」 |
| **有償化条件** | 院長の意思 + リスト月次化の見込み + 反応実績、の3点セット |
| **有償化しないケース** | 「自分でやれる」「母数が少なすぎる」「本当の課題が別」 |
| **月額の正当化** | 時給ではなく「運用が止まらないこと」で訴求 |
| **初回パイロットで追わないもの** | 正確な率、売上換算、チャネル比較 |
| **Type B の注意点** | 手書き運用は初回だけ。2回目以降はCSV移行が有償化の前提 |
