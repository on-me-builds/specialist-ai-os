# specialist-ai-os
歯科医院向け 中断患者リテンションOS
外部共有用 事業計画案 v0.1
2026-03-23

---

# 背景
- 多くの歯科医院では、中断患者や取りこぼし患者が見えていない
- 問題は改善率以前に、誰を追うべきか整理されていないことにある
- 現場では、忙しさの中で対応が後回しになりやすい
- 数字が弱い医院でも、放置コストは確実に存在する

---

# なぜこのテーマか
- 予約システムやリマインド機能はすでに普及している
- ただし、中断患者の呼び戻しは機能があっても運用として回っていないことが多い
- 4文章生成だけでは継続課金しづらく、主商品としては弱い
- そこで、成果物ではなく運用づくりを主商品に置く

---

# サービス概要
予約システムはそのままで、取りこぼし患者を見える化し、戻せそうな人から呼び戻す運用を作るサービス

- 中断患者候補の整理
- 呼び戻し対象の優先順位づけ
- 文面作成
- 反応記録
- 再予約導線の整理

---

# 対象医院
- 既存患者が一定数いる歯科医院
- 予約システムや一覧はあるが、中断患者対応が属人的
- 院長または受付責任者が「気になっているが手が回っていない」と感じている
- LINE、SMS、メール、電話のどれかで患者に連絡できる

---

# 導入の進め方
- Type A: 予約履歴や CSV があり、そのまま対象候補を出せる医院
- Type B: 数字は弱いが、中断患者がいそうな感覚はある医院
- Type A は小規模パイロットに進みやすい
- Type B は2週間の見える化シートや手動整理から始められる
- データがない医院でも、現実的な範囲で着手できる設計にする

---

# 初期提供内容
- 対象患者の整理
- 呼び戻し文面の設計
- 医院側配信を前提にした運用設計
- 反応記録の残し方の整備
- 週次または月次の簡易振り返り

こちらが最初から医院の管理画面に深く入る前提にはしない

---

# 立ち位置と事業モデル
- 予約システムを置き換えない
- 既存システムの上に乗る運用改善層を狙う
- 4文章生成は front-end offer とインテーク資産として活用する
- 初期は無料または低額のパイロット、その後に月額運用支援を想定する
- 価格や標準範囲は、ヒアリングと実証で調整する

---

# 直近の検証計画
- 院長ヒアリングを進める
- Type A / Type B の候補医院を確保する
- 小規模パイロットを走らせる
- まずは見える化、対象抽出、配信実行、反応有無を確認する
- 継続意向と支払い意欲を見極める

---

# 現時点の前提
- 主対象は歯科のみとする
- いきなり全自動 SaaS 化はしない
- 最初の価値は KPI 改善より、見える化と最初の運用化に置く
- データが強い医院にも、弱い医院にも入れる形を優先する
- 現時点では仮説検証フェーズであり、未確定論点は実証で詰める
